Fake REST API

7 Januari, 2022 · 3 menit

Bikin aplikasi itu ada masalah ayam dan telur. UI butuh data biar bisa dibikin, tapi backend baru bisa dibikin kalau sudah tahu UI-nya butuh data apa.

Dulu aku selalu mulai dari backend. Bikin tabel, bikin endpoint, baru mulai bikin tampilan. Hasilnya hampir selalu sama. Begitu UI-nya jadi, ternyata butuh field lain, urutannya beda, atau satu halaman ternyata butuh data dari dua tempat. Backend yang sudah capek-capek dibikin harus dibongkar lagi, dan itu bisa kejadian tiga sampai empat kali dalam satu project. Waktu paling banyak habis buat bikin ulang sesuatu yang dari awal belum jelas bentuknya.

Cara lainnya, data tiruan ditulis langsung di kode frontend. Ini juga ada jebakannya. Isinya biasanya asal-asalan, kayak "test", "aaa", atau harga 123, jadi UI-nya kelihatan rapi terus. Giliran ketemu data asli, nama produk yang panjang bikin layout berantakan, harga jutaan nggak muat di kartunya, dan daftar seratus item ternyata lambat di-scroll.

Data tiruan kayak gitu juga nggak bisa diajak ngapa-ngapain. Tambah item, refresh, hilang. Nggak ada loading karena datanya langsung ada, dan nggak pernah gagal karena nggak ada server yang bisa mati. Dua keadaan itu akhirnya baru ketahuan bermasalah pas aplikasinya sudah dipakai orang.

Di IoT masalahnya lebih parah. Alatnya ngirim data ke server, server menyimpan, dashboard menampilkan. Tiga bagian itu saling tunggu. Mau ngetes firmware, server-nya harus ada. Mau ngetes dashboard, alatnya harus nyala dan ngirim data. Satu bagian belum jadi, semuanya ikut mandek.

Aku yakin ini bukan cuma masalahku. Frontend developer yang nunggu tim backend, mahasiswa yang dikejar deadline tugas, orang yang ngerjain project sendirian, sampai yang iseng main mikrokontroler di rumah, semuanya pernah kejebak di sini.

Layanan fake API online sebenarnya sudah ada. Tapi datanya sudah ditentukan, jadi bentuknya jarang cocok sama aplikasi yang lagi dibikin. Data yang ditambahkan juga cuma pura-pura disimpan, dan hilang lagi di request berikutnya.

Jadi aku bikin Jsons, fake REST API kecil dari satu file PHP dan SQLite yang jalan di laptop sendiri. Cara pakainya cuma satu: tempel JSON, kasih nama, simpan. JSON itu langsung bisa diambil dari aplikasi kayak API beneran.

Bedanya dengan data tiruan di kode, datanya diingat. Item yang ditambahkan dari UI masih ada setelah refresh, yang diedit tetap berubah, yang dihapus beneran hilang. Alur tambah, edit, dan hapus bisa dites dari awal sampai akhir tanpa satu baris kode backend pun.

Isinya juga bebas. Aku biasanya ambil contoh respons dari dokumentasi API yang nanti bakal dipakai, atau beberapa baris data asli yang namanya disamarkan. Cukup sekali, dan dari awal UI-nya sudah ketemu nama yang panjang, harga yang besar, dan field yang kosong. Masalah layout ketahuan di hari pertama, bukan minggu terakhir.

Kalau bentuk datanya ternyata salah, tinggal edit JSON-nya di browser. Nggak ada migrasi, nggak ada endpoint yang harus diubah. Bongkar pasang yang dulu makan waktu berhari-hari sekarang cuma beberapa detik.

Loading dan error juga bisa dipancing dengan nambah satu parameter di URL: 

/products?delay=2000
/products?status=500

Yang pertama bikin respons datang dua detik kemudian, yang kedua bikin server pura-pura error. Skeleton, spinner, dan pesan error yang biasanya nggak pernah kelihatan akhirnya bisa dicek.

Buat IoT, Jsons jadi titik tengah yang bisa dipakai duluan. Alatnya ngirim pembacaan sensor ke Jsons, dashboard-nya membaca dari situ. Tombol di dashboard mengubah status relay, alatnya mengecek status itu tiap beberapa detik. Firmware dan dashboard bisa dikerjakan terpisah, dan masing-masing bisa dites tanpa nunggu yang lain jadi.

Setelah UI-nya jelas, barulah aku tahu backend-nya harus kayak gimana. Backend dibikin sekali, sesuai kebutuhan yang sudah terbukti, dan aplikasinya tinggal diarahkan ke alamat yang baru.

Jsons tentu bukan pengganti backend. Nggak ada login, jadi siapa pun yang bisa menjangkaunya bisa mengubah datanya. Pakai di laptop atau jaringan rumah sendiri aja, jangan dipasang di internet. Nggak ada relasi dan validasi juga, karena memang cuma dimaksudkan jadi tempat sementara.

Tapi buat ngelewatin fase paling membingungkan dari bikin aplikasi, waktu belum tahu mau bikin apa, ini sudah lebih dari cukup.
